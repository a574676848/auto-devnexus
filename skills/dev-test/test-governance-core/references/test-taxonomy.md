# Test Taxonomy

## 通用测试视角

所有测试类型默认站在 QA/QC 视角执行。围绕操作方式、验收标准、关键断言、缺陷证据、质量风险和放行建议形成结论。用户已经澄清的信息必须记录并复用，记录位置必须是被测项目 `test-governance/reports/clarifications.md` 或本次报告同目录小节，不写入用户级别目录；除非出现新的阻断点、信息过期、环境切换、权限变化或数据写入风险变化，否则不重复澄清。

所有测试输入、命令参数、终端输出、脚本、日志、报告和证据文件必须使用 UTF-8 编码。除冒烟测试外，执行型测试必须模拟人工操作，至少覆盖真实浏览器、真实客户端、真实 CLI 或等价用户路径；接口调用只能作为辅助证据，不能作为唯一验证方式。

## 操作方式规范

| 测试类型 | 操作方式 | 说明 |
| --- | --- | --- |
| 常规测试（单元/组件/逻辑） | 模拟操作（mock/stub/fake） | 隔离外部依赖，仅验证被测单元自身逻辑 |
| 冒烟测试 | 可选（模拟或真实均可） | 快速验证构建或环境可用性，不做深度断言 |
| 集成测试 | **必须模拟人工操作** | 使用真实浏览器、真实客户端、真实 CLI 或等价用户路径驱动真实服务、真实数据库、真实 API；接口调用只作辅助证据 |
| UI 测试 | **视觉比对 + 必要人工路径证据** | 视觉比对负责设计稿一致性；涉及功能行为时必须归入集成/e2e 并模拟人工操作 |

## 测试用例

面向验证目标的结构化说明。至少包含：编号、标题、类型、优先级、前置条件、步骤、预期结果、数据、证据方式、自动化状态。

## 单元/组件测试（常规测试）

验证最小可测单元的行为。采用模拟操作，隔离外部依赖。

通过标准：

- 被测函数/方法/组件的输入输出符合预期。
- 外部依赖（数据库、网络、文件系统）被 mock/stub/fake 替代。
- 异常路径和边界条件覆盖。

## 冒烟测试

验证构建或环境是否值得继续深入测试。只覆盖 P0 主路径和关键依赖可用性。操作方式可选：模拟或真实均可。

通过标准：

- 服务能启动。
- 核心入口可访问。
- 关键登录或鉴权链路可用。
- P0 业务主路径至少能走通。

## 集成测试

验证模块、服务、数据库、外部依赖、API、消息队列或 CLI 与服务端协作。**必须模拟人工操作**：通过真实浏览器、真实客户端、真实 CLI 或等价用户路径驱动真实服务地址、真实数据库和真实 API，使用受控测试环境和独立测试数据；不得只做接口调用，也不得在集成测试中使用 mock 替代被验证的协作方。

优先级：

1. 鉴权、租户、权限边界。
2. 数据创建、读取、更新、删除主链路。
3. 外部服务适配器成功和失败路径。
4. 统一响应、日志、trace、审计。

## UI 测试

**验证产品原型或 UI 设计稿与实际渲染 UI 的一致性**，属于视觉比对范畴。包括：

- 设计稿与实现页面的布局对比（位置、尺寸、间距）。
- 色彩、字体、图标、圆角等视觉样式对比。
- 响应式断点下的视觉表现对比。
- 组件状态（hover/focus/active/disabled/error）的视觉对比。

UI 测试不负责验证业务流程正确性——浏览器功能操作（导航、点击、填写、表单提交、列表 CRUD）归入集成测试，通过 API + 真实浏览器工具完成。UI 测试也不能替代后端集成测试；视觉通过只证明设计与实现一致，不证明业务边界完整。

工具选择：

- 视觉比对优先 Figma API + 像素比对工具（如 Percy、Chromatic、Playwright Visual Comparison）。
- 轻量手动比对可用 BrowserSkill 截图 + 设计稿叠加对比。
- 项目已有 Playwright/Cypress 时，复用其截图对比功能。

## 回归测试

验证 bug 修复或改动没有破坏既有行为。必须绑定原始问题、复现步骤和修复后断言。除冒烟回归外，必须模拟人工操作并保留真实用户路径证据，不得只做接口调用。

## 增量测试

基于 bug、diff 或影响面裁剪测试范围。目标是用最小成本覆盖最大风险，不等于跳过必要验证。除冒烟增量外，必须模拟人工操作并保留真实用户路径证据，不得只做接口调用。
