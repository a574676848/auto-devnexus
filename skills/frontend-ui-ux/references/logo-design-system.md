# 标志设计系统 (Logo Design System)

> 来源：[kaankiziltug/logo-design-skill](https://github.com/kaankiziltug/logo-design-skill)（MIT，commit `bbf31e5`），按本技能语义重写。
> 本文件是模式 I 的执行规范；品牌全案画板与流派配色见 `brandkit-and-identity.md`。

标志是**识别符，不是说明书**：简单、独特、相关，16 px 能认、楼顶能挂、单色能用、十年不过时。
工作目标只有三件：找到一个清楚的想法，用工艺把它画准，证明它能用，再按正确标准呈现给用户。

---

## 1. 子模式分流

| 用户诉求 | 子模式 | 起点 |
| :--- | :--- | :--- |
| 新做一个标志 | 设计（完整或快速通道） | 第 2 节阶段 1 |
| 点评现有标志 | 评审 | 第 6 节红旗清单 + 第 7 节测试清单打分 |
| 焕新或替换 | 重设计 | 先做资产盘点（保留哪些识别要素），再走设计阶段 |
| 规范、子品牌、图案、动效 | 系统 | `brandkit-and-identity.md` 画板体系 |
| 从现成标志导出 favicon / App 图标 / 变体 | 资产 | 第 8 节 `export_variants.py` |

**快速通道**：信息少或用户要立刻看结果时，一条消息最多问 5 个问题；或者直接写明假设，跳到三个概念。

**概念检查点（硬规则）**：设计与重设计流程在阶段 6 必须停下，先展示概念总览图、每个概念一句话和推荐，再询问是否制作完整标志套件。
套件是大部分工作量，只对已认可方向有意义。只有用户明确说「不用问，全部交付」才跳过；用户无法回复时也停在检查点，并描述套件会包含什么。

## 2. 七阶段工作流

### 阶段 1：需求发现 → Brief
收集：准确拼写的名称、业务、受众、3 到 5 个品牌形容词、竞品、约束（既有颜色、资产、使用场景）、拍板人。
写一份短 Brief 并列出假设。**形容词是最有价值的输入**，它们会直接转成视觉线索。

### 阶段 2：调研与策略
1. 看清品类长什么样，目的是避免泯然众人。真实参考库随技能收录，直接查：
   `python vendor/logo-design-skill/skills/logo-design/scripts/search_library.py --industry developer-tools --summary`
   行业值写错不报错但会 0 命中，取值见 `vendor/README.md`；查完挑 3 到 5 个文件真正读一遍它们的 SVG 构造。
2. **显式列出品类陈词滥调**并默认禁用（金融科技：蓝色、上升箭头、盾牌、地球；咖啡：豆子、热气、杯子），除非给出真正新鲜的形式。
3. **词语地图**：名称、产品、形容词、承诺 → 名词、隐喻、反义词，圈出交集。
4. 选候选标志类型（第 3 节），至少探索两种不同类型。

### 阶段 3：概念
- 写 **8 到 12 个一句话概念**，分布在不同类型上。每个都要有可拥有的转折；一句能套到竞品身上的话不算概念。
- 快速打分（想法清晰度、区分度、简洁度、相关性、小尺寸强度），选出**最强且彼此最不同的三个**。
- 一句话便宜，构建昂贵：只构建这三个，不打磨会被丢掉的想法。
- **动手前先查重**：`search_library.py --subject <事物>` 或 `--query <词>` 确认不是在复刻已有标志，再挑 3 到 5 个同技法范例研究几何怎么搭。

### 阶段 4：SVG 构建（先黑后彩）
- 先用文字描述构造（基本形、半径、角度、网格单位），再写 SVG。符号画布 `viewBox="0 0 256 256"`，组合标高度保持 256、宽度随内容。
- 纯黑白底，不上色。锚点少，圆形几何用弧线，角度只用 0/15/30/45/60/90°，描边宽度与圆角统一，负空间用 `fill-rule="evenodd"` 挖真孔。
- 成品标志禁止 `<text>`，字母一律构造成路径；探索期可用 `<text>` 但必须标注。
- 每次有意义的迭代另存（`concept-a-v1.svg`、`-v2.svg`），不覆盖，方便对比。

### 阶段 5：测试与打磨（至少循环两轮）
跑 `svg_audit.py` + `preview_sheet.py`，**打开渲染结果亲眼看**。用 SVG 代码画图等于蒙眼作画，改完必须渲染再看。
- **尺度**：想法在 16 到 24 px 仍成立；缝隙和描边够大，否则简化或另做小尺寸版。
- **视觉校正**：圆形与尖角外溢约 1% 到 3%；修圆角的骨头效应；水平笔画略细；视觉中心略高于几何中心；反白版略减重。
- **平衡**：稳定、没有意外倾斜、重量均匀、符号外框接近正方形。
- **误读**：镜像、旋转 180°、缩到极小，检查有无意外形状或含义。
- **区分度**：与竞品并排的货架测试；熟悉感测试（觉得眼熟又不是你的，那就是别人的）。
- **工艺关（AI 画标志最常翻车处）**：①字母测试，每个改造字母第一眼仍读作原字母；②接缝检查，笔画交汇处无缺口、细刺、鼓包；③同侪测试，与 3 到 4 个优秀标志同尺寸并排，完成度不能更低；④直白度，概念若只是把产品画出来（咖啡店画杯子），继续推进或放弃。

### 阶段 6：展示概念并停下（检查点）
用 `concept_sheet.py` 或 `preview_sheet.py` 产出总览图，**先灰度**（颜色会引发口味之争），推荐方案可加一点色彩提示。消息格式：

```markdown
<概念总览图>

### A · <名称> · <标志类型>  ← 推荐
**想法**：<一句话>
**为什么合适**：<2 到 3 条，挂钩 Brief 的形容词、受众、竞品>

### B / C（同结构）

**我的推荐**：<一两句，含每个概念的一个诚实风险>
**下一步**：选定方向（或说出各自喜欢的点）。是否为该方向制作完整标志套件？
套件包含：配色及单色/反白版、横版与竖版组合、小尺寸版、favicon + App 图标 + Web 图标集、行业样机展示板、一页使用规范。
```

图负责说话，消息保持短。此时不附变体、展板或图标集。用户要求修改则回到阶段 4 到 5。

### 阶段 7：制作套件（仅在用户同意后）
1. **定稿几何**：最终几何、视觉校正、小尺寸版、减重反白版。
2. **配色**：理想 1 到 2 色，品类内可拥有，可复现（HEX/RGB/CMYK/Pantone），满足可访问性；单色与灰度版必须依然成立。
3. **字体与组合**：字体研究、定制字母以建立所有权、视觉字距、最多两个字族；横版、竖版、纯符号、纯字标，锁定相对尺寸与间距。字体许可必须允许用于标志。
4. **展示板**：行业相关样机（咖啡店用杯子和纸袋，开发工具用 README 和终端），版式沿用 `brandkit-and-identity.md` 的 3×3 或 2×3 画板。
5. **导出文件**：`export_variants.py`（第 8 节）。
6. **规范与交接**：安全空间（以标志内某元素为单位）、最小尺寸、色值、许可背景、误用示例；母版 SVG；交接说明写清理由、测试结果与遗留项。

## 3. 标志类型与选型

| 类型 | 适用 | 风险 |
| :--- | :--- | :--- |
| **字标 Wordmark** | 名称短、独特、可读性就是资产 | 默认字重的几何无衬线毫无所有权，必须定制字母 |
| **首字母标 Monogram** | 名称长、需要小尺寸符号 | 通用首字母 + 未修改字体 = 不可注册、不可记忆 |
| **字母形符号 Letterform** | 单个字母承载一个隐喻 | 改造过度后字母不可读（字母测试必过） |
| **具象图形 Pictorial** | 有可拥有的具体意象 | 剪贴画式直白（牙医画牙、地产画房子） |
| **抽象图形 Abstract** | 业务宽、需要长期延展 | 意义空洞，需要靠系统和时间建立认知 |
| **徽章 Emblem** | 传统、机构、社群、餐饮 | 小尺寸细节糊掉，必须另做简化版 |
| **吉祥物 Mascot** | 消费级、亲和、需要表情系统 | 维护成本高，16 px 基本不可用，需配简化符号 |
| **组合标 Combination** | 新品牌起步，符号尚无认知 | 符号与字标必须能拆开单独使用 |

构型思路沿用 `brandkit-and-identity.md` 第 2 节的 5 大构型法（字母隐喻、产品动作、双隐喻聚变、负空间、几何系统），本表决定载体，构型法决定想法。

## 4. SVG 构建规则

**文件约定**
- 整数画布：符号 `0 0 256 256`（或 512）；组合标高度 256、宽度随内容（如 `0 0 960 256`）。
- 内边距统一（符号约 4% 到 8%），或紧贴裁切交给安全空间规则，整套保持一致。
- 坐标取整数或 1 到 2 位小数；`127.99999` 这种精度既膨胀文件又掩盖错位。
- 带 `<title>`；按 `<g id="symbol">`、`<g id="wordmark">` 分组，方便重组；一变体一文件，命名可预测（`brand-symbol-black.svg`）。

**构造策略**
- 先用文字写构造：「圆 r=96 居中 (128,128)，右上切掉 45° 楔形，r=28 小圆落在缺口里当点」。
- 选一个网格单位（256 画布上取 8 或 16），关键尺寸吸附到倍数；记录用过的半径与角度并复用。
- 基本形用 `<circle>` / `<rect rx>` / `<polygon>`，其余与最终合并轮廓用 `<path>`。

**路径**
- 圆形几何用 `A` 弧线；有机曲线锚点放在极值点、手柄水平或垂直；四分之一圆的三次贝塞尔手柄长约 0.5523 × r。
- 锚点越少越好；需要很多点的曲线拆成弧线。
- 斜线端点按精确角度计算（30°/60° 用 0.5 与 0.866，45° 等量偏移），禁止 44° 这类差一点的角度。
- 防骨头效应的平滑圆角：曲线在拐角前约 1.3 × s 开始，手柄约 0.6 × s。
- 闭合填充路径一律以 `Z` 结尾。

**负空间与复合形**
- 外轮廓与孔放在同一条 path，用 `fill-rule="evenodd"`，或反向绕行配默认 `nonzero`。
- 隐藏图形先画负形（箭头、字母），再围绕它构建正形，保证负形干净。
- 同色相接的形合并成一条 path，避免渲染或切割时出现发丝缝。

**描边与填充**
- 探索期用描边（`stroke-linecap="round"`）提速；母版应转成填充轮廓。没有轮廓化工具时，直接按半描边宽偏移构造轮廓，或保留描边并在交接说明中注明需要在矢量编辑器里扩展。
- 单线标志若要在 24 px 可读，描边宽度不低于标志宽度的 8%。
- 装了 Inkscape 可命令行扩展描边并合并：`inkscape logo.svg --actions="select-all:all;object-stroke-to-path;path-union;export-plain-svg;export-filename:logo-outlined.svg;export-do"`。

**母版禁用项**

| 禁用 | 原因 | 替代 |
| :--- | :--- | :--- |
| `<text>` | 依赖字体 | 轮廓化路径 |
| `<image>` / 内嵌位图 | 非矢量 | 矢量路径 |
| `filter`（模糊、阴影、发光） | 渲染不一致，无法印刷 | 平面形，用更深色的形模拟阴影 |
| 多层 `mask` / `clipPath` | 工具兼容差 | 烘焙进路径 |
| 深层嵌套 transform | 难编辑、累积误差 | 坐标直接换算（单层外包 translate/scale 可接受） |
| 20+ 颜色或大量渐变 | 复现差、记忆弱 | 不超过 3 个平色；渐变必须同时保留平色母版 |
| 小于尺寸 1/64 的细节 | 缩小即消失 | 合并或删除 |

颜色直接写在元素上（`fill="#…"`），不用 `<style>` 块；渐变用 `gradientUnits="userSpaceOnUse"` 加显式坐标。

## 5. 十二条原则

1. **先问谁、做什么、为什么**：让问题决定方案，为业务将去的方向设计。
2. **识别，不解释**：一个路标，不是服务目录。
3. **简单但不平庸**：减到想法清楚，再保留一个可拥有的细节。
4. **相关但不直白**：唤起态度，不要画产品；熟悉符号的新鲜形式可行。
5. **独特**：了解品类，然后偏离大家都在用的样子。
6. **好记**：形状与颜色是第一记忆钩子，只留一个决定性特征。
7. **一个想法**：一句话能讲清；轻微谜题是好事，谜语不是。
8. **大小通吃**：16 px 到 16 m，单色、反白、刺绣都成立。
9. **永恒胜过潮流**：建立在概念上，而不是效果上。
10. **系统的根基**：不要在真空中评判标志，它要能长出图案、图标与动效。
11. **工艺决定成败**：几何、视觉校正、间距，看不见的细节区分好与优秀。
12. **坚定而不固执**：捍卫策略，对细节保持开放，重视反馈。

## 6. 红旗清单（出现任一项，先修再展示）

- 剪贴画式直白，或品类陈词滥调没有任何转折。
- 通用首字母配未修改的现成字体；默认字重几何无衬线，毫无可拥有之处。
- 超过三种颜色且没有概念理由；用渐变或阴影去救一个弱形。
- 细节小于标志约 1/48、发丝线、小尺寸下会闭合的窄缝。
- 差一点的角度、锚点过多导致的鼓包曲线、描边粗细不一。
- 「终稿」里还有 `<text>`、内嵌位图、滤镜或遮罩。
- 需要一段话才能看懂的概念。
- 看起来像任何现存标志。

## 7. 测试清单

**尺度**：16 px favicon 核心想法仍在（不行就做简化小尺寸版）；24 到 32 px 一眼可认；超大尺寸曲线平滑、无鼓包；记录最小可用尺寸（屏幕 px、印刷 mm）。

**颜色与明度**：黑色单色；白色反白（不比黑版显重，否则出减重反白版）；品牌色底、照片底、图案底（不行就加外框或容器）；灰度下色块仍按明度分开；CMYK 可复现，鲜艳色有专色对应。

**形态**：眯眼/模糊测试轮廓仍独特；镜像暴露比例问题；旋转 90° 与 180°、缩小、远看，排查意外字母、身体部位、冒犯或政治宗教符号、类似警示标志；视觉校正已做；几何干净；平衡不歪；字母测试、接缝检查、同侪测试全过。

**独特性**：竞品货架测试突出；熟悉感测试通过；建议用户做商标检索与以图搜图，明确告知我们无法给出法律意义上的商标清查结论。

**意义与匹配**：一句话讲清；调性对上形容词（锐/圆、重/轻、暖/冷、经典/现代）；业务扩张后仍适用；目标受众文化下的颜色与符号含义已核对；去掉标语、最终去掉名称后符号仍能工作。

**媒介与生产**：单色印刷、刺绣（无发丝线，胸标尺寸缝隙约 1 mm 以上）、激光雕刻、刻字、招牌、暗色模式、动画；App 图标在平台圆角格内视觉居中、无细小文字；圆形头像裁切后仍成立；母版纯矢量、文字已轮廓化、描边已扩展、无滤镜与位图（`svg_audit.py` 约 90 分以上且无 FAIL）。

**情境**：5 到 6 个与业务相关的真实样机（咖啡店用杯子，不用健身包），风格统一；各组合版在预期尺寸下都测过。

**记录结果**：展示时说明通过了什么、调整了什么（如「反白版减重 3%；把字怀缺口从 6 加到 10 个单位，保证 16 px 不糊」），以及用户仍需做什么（商标检索、Pantone 打样）。

## 8. 脚本与参考库

两处，各管一段：

| 位置 | 内容 | 什么时候用 |
| :--- | :--- | :--- |
| `scripts/logo/` | 精简版 5 个脚本（`svglib`、`svg_audit`、`preview_sheet`、`render_png`、`export_variants`），无参考库也能跑 | 只做体检、测试页、变体导出 |
| `vendor/logo-design-skill/skills/logo-design/` | 上游完整 9 个脚本 + 14 份参考文档 + 模板 + **1,432 个真实标志 SVG 库** | 查品类惯例、货架对比、概念总览图、客户提案展板 |

两处都是纯 Python 3 标准库。Windows 上 `python3` 常是应用商店占位程序，一律用 `python`（或 `py -3`），路径写全。

| 脚本 | 用途 |
| :--- | :--- |
| `search_library.py` | 按类型/技法/几何/行业/情绪/主色检索 1,432 个真实标志；`--summary` 看品类惯例，`--exemplary` 只取范例，`--format paths` 给文件路径，`--list-values` 列全部合法取值 |
| `preview_sheet.py` | HTML 测试页：尺寸阶梯、16/32 px、多背景、单色、眯眼模糊、镜像旋转、favicon/App 图标/页头情境；`--refs` 指定竞品文件，`--refs-industry` 直接从库里拉同行业标志做货架对比 |
| `svg_audit.py` | 结构体检：活文字、位图、滤镜、颜色数、渐变、描边、差一点的角度、微小细节、居中、复杂度，输出 0 到 100 分 |
| `render_png.py` | SVG 渲染为透明 PNG（自动挑 cairosvg / rsvg-convert / Inkscape / 无头 Chrome）；`--which` 列出可用渲染器；可截图 HTML、生成 `favicon.ico` |
| `export_variants.py` | 黑、白、品牌单色、方形、favicon、App 图标 SVG；`--png` 导出尺寸；`--web-icons` 生成 favicon.ico + PNG 图标集 + webmanifest + `<head>` 片段 |
