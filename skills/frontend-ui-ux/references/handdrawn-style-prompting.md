# 手绘插画与编号化提示词系统 (Handdrawn Style Prompting)

> 来源：[yang0/handraw-style](https://github.com/yang0/handraw-style)（MIT + 署名要求，commit `ab848eb`）。按许可要求保留署名：作者 **yang0**，仓库 `https://github.com/yang0/handraw-style`。
> 本文件是模式 D（生图）的补充规范：界面原型走分节生图，插画类资产走这里的编号化方法。二者共用同一套 prompt 骨架，见 `image-generation-prompts.md`。

适用场景：文章封面与配图、海报、小红书组图、信息图、漫画分镜、IP 形象、电商图，以及需要统一画风的批量出图。

上游是 370 种画风 + 170 种版式 + 36 种主题色的大型图鉴，本文件只提炼**能迁移的方法**，不搬运图库。

---

## 1. 编号系统（选型语言）

| 维度 | 编号格式 | 规模 | 作用 |
| :--- | :--- | :--- | :--- |
| 画风 | `FA` 到 `FI` 九个族 + 三位序号（如 `FB-020`、`FI-001`） | 370 种 | 决定笔触、媒介、质感、整体视觉语言 |
| 版式图型 | `SC`（社媒卡 24 种）/ `IG`（信息图 38 种）/ `SB`（漫画分镜 71 种）/ `IP`（IP 设计 13 种）/ `EC`（电商 24 种） | 170 种 | 决定构图拓扑、层级与文字排布 |
| 主题色 | `C-01` 到 `C-36` | 36 种单色 | 决定主色与情绪，六组各六色：经典蓝、清新绿、古典红绿、浪漫粉紫、暖阳大地、中性 |

九大风各族：FA 国际社论幽默、FB 经典绘本叙事、FC 现代平面艺术、FD 日本当代插画、FE 新国风与传统工艺、FF 3D 黏土毛毡与纸雕、FG 动漫与赛璐璐、FH 先锋实验综合媒介、FI 写实摄影与视觉大片。

**编号只是选型语言，不是画面内容**。提示词正文里出现 `#018`、`SC-021`、`C-01` 这类编号，生图模型会把它们当成文字画到画面上。正文一律用自然语言名称（如「细线都市小品」「鼠尾草绿」）。

**版式的两类执行机制**
- **确定性静态版式**（绝大多数 SC / IG / SB）：拓扑固定，直接把版式模板、画风与主题拼接成提示词即可。
- **高维动态版式**（如「照片转译双拼卡」这类）：不是固定线框，而是跨媒介构图语法。此时助手要当设计总监先做决策（切分方向、转译类型、背景净化），再输出单一、排他的执行提示词；不能把备选清单平铺给模型，否则它会退化成机械照搬。
- 比例驱动切分：竖版（3:4、9:16、1:2）默认上下堆叠；横版（16:9、4:3、21:9）默认左右并排；方版 1:1 按用户指定或自适应。

## 2. 两种输出模式

| 模式 | 行为 | 何时用 |
| :--- | :--- | :--- |
| **纯图 pure-image**（默认） | 只给画面内容，不安排文字；回答末尾提示「当前处于纯图模式，可切换为图文模式」 | 插画、封面主视觉、IP、摄影风 |
| **图文 graphic-text** | 主题**逐字保留**，不扩写、不引申、不加场景人物；在提示词末尾原样追加图文后缀 | 海报、社媒卡、信息图、带标题的封面 |

指定了版式编号时自动切图文模式（电商版式 `EC-*` 除外，它不追加通用图文后缀，也不擅自拼画风）。

**图文后缀（中文，逐字原样追加，不改写不翻译不调整顺序）**

```text
【如果主题直白包含画面元素那就按主题出图，文案由你来升华，但是不要直接描述画面。 如果主题比较概念化，那么文案和主题尽量保持一致，如果文案较长由你提炼，由你先设计画面隐喻（人类和非人类都行）再出图   。    文字参与构图，图文一体】
```

## 3. 自动推荐策略（最容易写坏的地方）

用户没指定画风或主题色时，**默认由 AI 实时研判给出推荐，绝不因为缺编号而中断或拒绝**。

**核心禁令：不得维护任何「主题关键词 → 固定编号」的静态映射**。一见节气就推某个编号、一见自然就推某个编号、一见科技就推某几个编号，这是最典型的偷懒，直接把 370 种画风压成十几种。

正确做法：
- 每次结合主题的深层语境、精神内核、视觉隐喻与构图，在**全库范围内开放匹配**。
- 同一个主题在不同切入点下有多种可能（「菜园」可以是水墨写意、田园木刻版画、粗粒油画棒、包豪斯几何），推荐要体现这种多样性。
- 推荐理由必须**具体到笔触与色彩为何能传达这个主题**，不用套话。

四种输入组合的处理：

| 用户给了什么 | 处理 |
| :--- | :--- |
| 都没给 | 推荐一组「画风 + 主题色」（单色统领、双色主次、三色调和都可以），一句具体理由，直接出完整提示词 |
| 只给画风 | 严格保留画风，推荐协调的主题色 |
| 只给主题色 | 严格保留主题色，推荐契合的画风 |
| 两者都给 | 完全遵照，不擅自替换 |

## 4. 参考图与改图（决定成败的两条硬指令）

**参考图隔离指令**（用户传了参考图，只借画风不借内容时，必须注入）：

```text
所附图片仅用于参考画风。只提取参考图的风格特征，例如线条、笔触、媒介、材质、色彩倾向和整体视觉语言；不要使用、复制或延续参考图中的任何主体、人物、动物、服装、道具、动作、姿态、场景、背景、构图、布局、文字或故事。最终画面内容完全以用户提供的主题为准。
```

English：

```text
Use the attached image only as a style reference. Extract only its stylistic qualities, such as linework, brushwork, medium, material texture, color tendencies, and overall visual language. Do not use, copy, or carry over any subject, person, animal, clothing, prop, action, pose, setting, background, composition, layout, text, or story from the reference image. The user's written theme is the sole source for the image content.
```

**改图重绘指令**（用户要把照片改成手绘风格时，必须追加，否则模型会在照片表面叠滤镜）：

```text
【请只提取人物的五官特征和姿态，场景轮廓，在画风上严格按 选择的风格重新画，不要在原照片上加质感。】
```

English：

```text
[Extract only the character's facial features and posture, and the scene contours. Strictly redraw from scratch according to the selected style; do not add texture or filters onto the original photo.]
```

配套规则：
- 用户不传图也完全可以纯文本直出，绝不强制索图、绝不因缺图断流。
- 图文模式下，参考图不要写进可复制的提示词里，也不要在提示词内写本地路径或上传说明；把图单独展示给用户，让他自己垫。
- 用户主题是主体与叙事的唯一来源，参考图不得覆盖或追加内容。
- 只保留正向可见特征，遇到带「避免」「不要」「禁止」的负向条款要过滤掉，不要机械照抄特征字段。
- 编号图缺失或传不进去时如实说明限制，给正常文本提示词，**绝不虚构一张替代参考图**。

## 5. 提示词构建规范

**结构**（中英双语两份，各一段，可直接粘贴）：

1. 开头声明风格名：中文 `风格名称：{名称}。`，英文 `Style name: {Name}.`
2. 有主题色时加一句：`主题色：{中文名}。` / `Theme color: {English name}.`
3. 只描述用户给的主题与约束；主题为空时给显式占位符（如「请在此输入画面主题，或在生图模型中垫入你的照片」），不要停下来追问。
4. 需要时追加 `核心风格特征：...`（仅正向、仅渲染风格，不改变主体与故事）。
5. 改图/垫图时追加第 4 节的固定重绘指令。

**禁止**：自创视觉特征、额外风格描述、通用质量词与构图套话、默认负面清单、把作者名气当作能力依据。命名参考作者只是索引标签，不是模仿指令，也不代表对其人的任何主张。

**一致性**：批量出图（组图、漫画、IP 多视图）时，画风名与主题色全程锁定，人物靠自建图库垫图保持一致，而不是靠反复加文字描述。

**自建图库**：角色库、道具库、场景库里的资产一律以**纯参考图垫图**参与出图，提示词里不写冗长外貌描述；跨媒介调用时形象与特征不会漂移。

## 6. 与本技能其它模块的分工

| 需求 | 走哪条线 |
| :--- | :--- |
| 网页 / App 界面原型、整站视觉稿 | `image-generation-prompts.md`：一屏一图、构图锚点、移动端真机框架 |
| 插画、封面、海报、组图、IP、电商图 | 本文件：画风编号 + 版式编号 + 主题色 + 双模式 |
| 标志、图标、品牌符号 | `logo-design-system.md`：矢量构建，不靠生图 |
| 营销页里的产品示意界面 | `faux-product-ui-stageshow.md`：代码构建，不用生图冒充 |

禁止混用：界面原型不要用插画版式模板（会得到漂亮但读不出信息的图），标志不要用生图（无法矢量化、无法小尺寸），产品截图不要用生图伪造。

## 8. 出图前自检

- [ ] 画风、版式、主题色选定，且提示词正文里**没有出现任何编号**。
- [ ] 主题逐字保留（图文模式），没有被我扩写或引申。
- [ ] 需要垫图时，隔离指令或重绘指令已追加，且是固定原文。
- [ ] 提示词只含正向描述，没有抄进「避免 / 不要 / 禁止」类条款。
- [ ] 中文一段、英文一段，各自可独立粘贴使用。
- [ ] 批量出图时画风名与主题色全程一致，人物靠垫图而不是靠描述维持一致。
- [ ] 纯图模式已提示可切换图文模式（同一会话只提示一次）。
- [ ] 没有声称生成过实际未生成的图。
