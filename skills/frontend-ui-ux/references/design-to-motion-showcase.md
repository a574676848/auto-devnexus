# 设计转动态展演 (Design to Motion)

展演不是重设计。观看者必须看到 **那张原样的设计**，并且看到 **它是活的**。

**精确帧 → 空态 → 平滑载入 → 每个视觉演出自己的故事 → 无缝循环。**

三段式：**A 保真重建**（成品帧与源稿不可分辨）、**B 动效系统**、**C 录制导出**。A 未过不许动 B，A7 与 B9 未过不许编码。

适用范围：Figma 帧、界面卡片、看板、App 屏、营销首屏、产品 Mockup、放在照片背景上的设计稿。
不适用：产品内的交互动效（hover、菜单、Toast），那属于 `motion-and-interactions.md` 的范畴。

---

## 1. 先定上下文 (Two Contexts)

上下文决定动什么、怎么开始结束、交付什么。动手前先定死。

| 维度 | **展演 (Showcase)** | **站点 (Website)** |
| :--- | :--- | :--- |
| 典型请求 | “把这张设计动起来”，只给一个 Figma 链接 | 在建/改落地页或站点，或请求点名了站点 |
| 动效范围 | 整帧 | 只动合资格分区（见下表） |
| 起始 | 页面加载，从空态起 | 分区滚动进入视口，只播一次 |
| 入场之后 | 故事跑完，整帧溶解，循环重来 | 故事常驻。不溶解，不循环 |
| 文本 | 导出图层，成品帧逐像素精确 | 站点字体的活 HTML，保 SEO 与无障碍，只导出视觉部件 |
| 交付物 | 页面 + MP4、网页 GIF、800×500 GIF | 站点代码内的动效分区，被点名才导出 |

判不准时看工作位置：在站点代码库内 → Website；只有设计稿没有站点 → Showcase。仍然含糊就问一次。

### 1.1 站点分区映射（哪些区做，哪些区不做）

按区扫描，只对有视觉部件的分区 + 首屏应用本模块，其余纯文本分区一律不做。

| 分区 | 处理 |
| :--- | :--- |
| **首屏（必做）**，无论有没有视觉 | 页面加载时的首屏入场（见 1.2）。首屏内的视觉再走各自那一行 |
| Bento / 特性区：文配图的卡片（图表、列表、流程、日历、提示词、播放器） | 滚动时卡片级入场（第 9 节的 `card` 类型，含文本），随后每张卡的视觉演故事（第 11 节）。这是落地页的主用法 |
| 产品 / 看板 Mockup（App 首屏截图） | 滚动时的加载入场：表面在位，内容加载（第 6 节）。加载后是否继续演故事 **必须先问**，不得擅自加 |
| Logo 行、集成墙 | 跑马灯，或温和的点亮故事 |
| 纯文本区：标题块、证言、FAQ、定价、CTA、页脚 | 不做。用站点常规滚动揭示（`landing-page-system.md` 第 11 节） |

### 1.2 首屏入场规格（站点必做）

- **页面先空**：第一帧只有页面背景（若首屏有 App 框，则加其静态贴合表面）。没有文字、没有页头、没有按钮。
- **幅度极小**：每个元素只上浮 6px，从 2px 模糊转为清晰，并淡入。不滑远、不缩放、不弹跳，像页面落位，不像表演。
- **快且按阅读顺序**：页头 → 徽标 → 标题逐行 → 副标 → 按钮 → 证明行，间隔 50 到 70ms，整段在约 1.2s 内落定。
- **只播一次**：页面首次加载时播放，不随滚动重播。
- 首屏内的视觉（浮动卡片、产品 Mockup）在标题之后开始自己的入场。

站点通用约束：

- 用 `IntersectionObserver` 触发，下方分区约 30% 可见时开始，只播一次。**严禁滚动监听。**
- 分区的故事离屏时暂停时钟，回到视口恢复。
- 错峰只在分区内部按阅读顺序，不跨整页。
- 沿用站点自己的组件、Token、圆角与字体；保真依旧按分区逐块比对。
- `prefers-reduced-motion: reduce` 直接呈现终态，不做故事。

## 2. 保真源：Figma

- Token 只从安全存储读（环境变量或系统钥匙串）。**绝不打印、回显、粘贴进对话或提交。**
- `GET /v1/files/:key/nodes?ids=:node&geometry=paths` 拿树、边界、填充、效果、圆角。
- `GET /v1/images/:key?ids=:node&format=png&scale=2` 渲染 **参考帧**，成品静帧必须对齐它（第 8 节）。
- 记下帧的绝对原点，每个图层的位置是 `绝对边界 − 原点`。
- 返回的 CDN 图片链接会偶发断连：每次下载都重试，用完先校验 PNG 尺寸。

## 3. 保真源：截图或平面图

截图没有图层、没有精确值，也看不到被遮挡的部分。仍可做，但每个元素都要重建或从像素里抬起。第 4 节的导出表只适用于 Figma，本节替代它。

**问一次，然后继续**：在采集批次里问有没有 Figma 链接（结果更好）、最高分辨率导出（2x 或 3x、PNG、未裁切、非 JPEG）、若设计放在照片上则要原始背景图。都没有就用现有素材继续，并在交付时说明。

**定舞台**：测量前先定像素比。用图片宽度除以常见帧宽（1440 / 1280 / 1920 / 390），取能整除的那个，再用正文尺寸校验（UI 正文通常 14 到 18px）。舞台尺寸 = 图片尺寸 ÷ 像素比，单位 CSS 像素。截图缩放到舞台的 2 倍作为第 8 节的参考。

**按截图像素测量**：像素 `i` 覆盖 `i` 到 `i+1`，中心是 `i+0.5`；混用会让圆形偏半个像素。2 倍比下大量位置落在半像素上，保留它们。若成品整体差一个设备像素，是 Chrome 在吸附：把舞台按截图像素布局再整体 `scale(1/ratio)`，所有位移距离同比例缩放。

**元素制造优先级**（取第一个能用上的）：

| 元素 | 做法 |
| :--- | :--- |
| 表面、卡片、药丸、按钮、输入框、分隔线、进度轨 | **CSS 重建**。填充色取平坦区域的中位数，不用单像素；圆角按角部曲线量，边框按边缘剖面量。**渐变**：沿渐变方向每 10 到 20px 采一个点作为 stop，多段或不均匀过渡才准；另一轴也变化时叠第二层渐变。**阴影**：渲染候选，逐个跨边缘比对像素剖面，搜 blur / offset / opacity 直到误差不再下降 |
| 文本（站点） | 站点字体的活 HTML |
| 文本（展演） | 先认字体（问，或对常见 UI 字面肉眼比对：Inter / SF Pro / Geist / Manrope / DM Sans / Satoshi / Plus Jakarta Sans），在 HTML 里重排后叠加到参考图 2 倍图上对比：每行宽度误差 1% 内、基线误差 1 截图像素内才算接近（PSNR 判不了文字，正确字体也低分）。接近则保留活文本以便打字与计数，否则按下行抬起 |
| 平坦/渐变表面上的文字、图标、字形 | **抬起为透明层**：与你重建的表面色做反混合。单色内容按 `alpha = (bg − px) / (bg − fg)` 逐像素算，取对比最大的通道，存 `fg` 与该 alpha；实操先渲染你重建的表面，再对它反混合，而不是猜一个色。`fg` 按文本组（标题、段落、链接）估一次，不要逐框估。每框与容器边缘、相邻元素保持数像素净空，否则会粘连。多色像素（双色图标、彩边）退回 Unblend 到表面 |
| 简单图标 | 能认出图标集（Lucide / Phosphor / Heroicons / Material）就用 SVG 重绘，任何缩放都清晰；否则按上行抬起 |
| 线条与连接线 | 从像素追踪中心线（每列/每行笔画中点）画成 SVG 描边，即可做“画出”动画而不用遮罩技巧 |
| 图表 | 柱用 CSS 按实测高度，折线与面积用按列追踪的 SVG 路径，之后可动画 |
| 照片、头像、Logo、插画 | **裁切**，并按容器圆角做遮罩。这是唯一允许的矩形裁切 |
| 照片上的文字、徽标、图标 | 留在照片裁切内，只随照片整体移动，标注为不可分离 |

**看不见的内容不发明**：被别的元素盖住的部分（卡片后面的卡、下拉后面的列表、面板后面的背景）在图片里不存在。严禁悄悄编造。

- 平坦或渐变底：CSS 重建，空态才精确。
- 照片底：任何“卡片升起”的布局都需要原图，因为空态会露出卡片后面的东西。没有原图就先说明，并给两个选项：补画（属于猜测），或按 App 框处理（表面留着，只加载内容）。**绝不默默补画。**
- 元素重叠：选择不会露出隐藏区域的动效。故事确实需要露出时，把被盖住的元素完整 CSS 重建。
- 塑造可见形状的隐藏部分（从卡片下穿过的线、延伸到卡片下的色晕）：用连接可见两端的最简几何延续（直线或同半径弧），并标注为推测。

**分辨率**：抬起的图层与裁切与原图同清晰度。裁切像素占比大时，导出倍率不得超过截图自身的比；否则多重建一些 CSS 与 SVG。1 倍截图要预先说明成品会比 Figma 重建更软。

**故事限制**：抬起的文字可以打字与删除，但 **不能计数**，计数器需要同字体活文本。

**动前告知**：用一份短清单说明哪些是 CSS/SVG 重建、哪些是抬起或裁切、哪些无法分离、哪些是推测（字体、像素比、隐藏区域）。**严禁把截图整体当一个块动，或让带着旧背景的裁切图乱移来伪造保真。**

## 4. 图层导出（仅 Figma）

每个会动的元素独立导出 PNG，**3 倍**，每次调用批量 20 到 25 个 id。

| 情形 | 摆放 |
| :--- | :--- |
| PNG 尺寸等于 `absoluteRenderBounds`（文本层总是如此） | 按渲染边界摆放 |
| PNG 大于渲染边界（被父级裁切、效果均匀外溢） | `x = bbox.x − (pngW − bbox.w) / 2`；顶部未被裁切时用 `renderBounds.y`，否则按效果半径与偏移反推 |
| 外溢不均匀（带箭头的线、单侧方头的描边） | 取 `geometry=paths` 里的 `strokeGeometry` / `fillGeometry` 边界，不用公式 |
| 旋转矢量加大幅图层模糊（软色块） | 用 `use_absolute_bounds=true` 导出并按包围盒摆放；该区域低于约 45 dB 时再跑一次 PSNR 偏移搜索。色块可存 1 倍，损失不可见 |
| 零高或零宽的描边矢量 | `use_absolute_bounds=true` 会返回 null，去掉该参数导出 |
| 带模糊内容的蒙版组 | 锚定未被裁切的那条边（通常是蒙版底部加描边） |
| 弧、圆环、局部椭圆 | 用 `use_absolute_bounds=true` 导出 |
| 远大于其表面的图案或叠层 | 用 `use_absolute_bounds=true` 导出后裁到表面矩形 |
| 实例子级（id 形如 `I12:34;56:78`） | 常返回 null，导出父级实例 |
| 需要“画出”的线（虚实皆可） | Figma 把描边转成填充形状，没有中心线。自己写中心线，作为遮罩盖在导出的 PNG 上 |
| 烘焙进大图层的照片 | 照片节点单独再导一次。用骨架盖住烘焙照片，把独立照片层放在上层做 `photo` 解析；静息时必须等于参考 |

保持帧精确的规则：

- **展演里文本始终是导出图层**，绝不重排成 HTML（字距与行高对不上）。站点里文本是活 HTML。截图源没有导出层，按第 3 节文本两行处理。
- **保留 Figma 的 z 序**。静态层可以夹在动画层之间，顺序与树一致。
- **帧描边通常画在子级之上**：把卡片描边作为独立叠层放在被裁切内容之上，再与参考比对（卡内辉光会改变描边观感）。
- **子级各自运动的容器**：API 导出帧会连子级一起烘焙。子级需独立加载或表演时，用节点数据把容器 CSS 重建（填充、圆角、内描边含 `individualStrokeWeights`、效果），再逐个导出子级。
- **阴影映射**：Figma 的 blur 为 `R` 的投影，等价于单元素的 `box-shadow` blur `R`，或整组的 `filter: drop-shadow()` blur 约 `R/2`。两者同为高斯，都要与参考比对。
- **组阴影是并集的阴影**：投影落在多个贴合表面的组上（App 框）时，把所有表面放进一个静态容器用 `filter: drop-shadow()`；逐元素 `box-shadow` 会在表面交叠处加深。独立卡片各自在自己的 `card` 单元内带阴影，阴影随卡片移动。
- 跳过 `visible: false` 的层，以及被不透明形状压在下面的杂层。

**画线**（中心线遮罩法）：

```html
<svg class="ly" viewBox="0 0 1440 990" style="left:0;top:0;width:1440px;height:990px">
  <mask id="draw1">
    <path d="M193 832 V700 A45 45 0 0 1 238 655 H380" fill="none" stroke="#fff" stroke-width="8"
          pathLength="1" stroke-dasharray="1" stroke-dashoffset="1"/>
  </mask>
  <image href="data:image/png;base64,..." x="192" y="653" width="190" height="181" mask="url(#draw1)"/>
</svg>
```

在 JS 时钟上把 `stroke-dashoffset` 从 1 推到 0。`pathLength="1"` 免去测长度，宽描边遮罩可覆盖抗锯齿。沿线脉冲用同一路径的 `getPointAtLength` 取点。

## 5. 背景神圣 (Background is Sacred)

设计放在照片或纹理上时，背景是设计的一部分，不是装饰。多数情况下 App 框之外的整块画布都是背景。

- **它永不变化**：入场、循环、溶解、任何缩放中都不动。不移动、不模糊、不缩放、不淡化、不改色。
- **任何变体都保留它**：“只加载不缩放”的版本仍是同一设计同一背景，绝不为了简化而丢掉照片。
- **导出原图，不要渲染图**：`GET /v1/files/:key/images` 返回原始图像填充；按填充的缩放模式与 `imageTransform` 用 CSS 复现：拉伸填充带变换时，`background-size` 是帧尺寸除以变换缩放，`background-position` 是负偏移。
- **校验**：静帧的背景区域与参考比，目标 45 dB PSNR 以上。裁切或偏移错误会立刻暴露。
- **磨砂面板必须能看见照片**：带 `backdrop-filter: blur()` 的表面必须是背景之上的同级独立元素，不能放在 `filter` 或 `opacity < 1` 的祖先里。无头 Chrome 还需该元素带 `transform: translateZ(0)` 与 `z-index` 才会渲染。
- **复现不了就先说**：没有图片访问、纹理是生成的、填充缺失，都要告知并询问，**绝不默默换成纯色**。
- 照片存高质量 JPEG 或 WebP，不用 PNG。

## 6. 布局：App 框还是独立卡片

先判定布局类型，它决定空态里有什么、什么在动。

**App 框（贴合表面）**：由两个以上表面拼成一个整体的看板或 App 屏（侧栏 + 主体，常有几像素重叠）。只有这型有静态表面。

- **空态里表面已在**：侧栏与主体就位、完全不透明、从第一帧起静止。永不淡入、滑入、缩放、模糊。只有里面元素加载。
- **交界处保留 Figma 堆叠**：主体压在侧栏内容裁切之上，侧栏内容永不越界到主体，主体也永不滑过侧栏。
- 主体内的卡片是内容，照常加载。

**独立卡片（Bento、卡组、部件）**：彼此分离、中间有间隙的卡片，**不是**贴合表面。

- **卡片本身入场**：每张卡带阴影升起（第 9 节 `card`），按阅读顺序错峰，内容随后在卡内就位。
- 空态只有背景。

**两型共用**

- **每个容器按自身精确形状裁剪内容**，含逐角圆角。任何东西都不得溢出到邻居或背景上。
- **图像形表面**（封面头图、整卡铺满的图）先用其平均色占位，照片再载入其中。
- **嵌套内容也是内容**：托盘、工具条、内面板照常加载。

裁剪范式（坐标在裁剪内仍保持舞台坐标）：

```html
<div class="clip" style="left:113px;top:138px;width:305px;height:907px;border-radius:16px 0 0 16px">
  <div class="cin" style="left:-113px;top:-138px"><!-- 单元仍用舞台坐标 --></div>
</div>
```

```css
.clip { position: absolute; overflow: hidden; isolation: isolate; }
.cin  { position: absolute; width: var(--stage-w); height: var(--stage-h); }
```

## 7. 展演页面架构 (Showcase Architecture)

站点场景直接在站点代码内实现，按 1.1 的分区策略落地；下列时钟、单元、模式按分区复用。

- **单个自包含 HTML**：固定尺寸舞台，等比缩放适配视口；图片 base64 内联，重复图片去重；只对 `<img>` 等解码，CSS 渐变不算图片。
- **三种模式**：`?still` 精确静帧（也用于 reduced-motion）；`?loop` 按导出周期循环；`?capture` 关闭 `requestAnimationFrame`，暴露 `window.__start()`、`window.__tick(dt)` 与循环时间 `window.__lt`，由录制器驱动时钟。
- **单元**：每个动画元素包一层全舞台尺寸的 `.u` 并携带延迟 `--d`。入场用基于 `.stage.in` 的 CSS transition。因为单元覆盖整舞台，其 `clip-path` 或 `transform-origin` 的百分比指向舞台，不是元素；必须用按元素矩形算出的像素值。
- **静态层保持合成**：裁剪层与描边叠层加 `transform: translateZ(0)`，避免邻近过渡开始时抗锯齿跳变（否则每次循环起点 1px 边缘闪烁）。
- **单一时钟**：一个 `requestAnimationFrame` 驱动全部时间相关效果（遮罩、扫光、故事、点缀），由循环时间驱动而非墙钟，录制才可复现。`?capture` 下时钟只由 `__tick` 推进。
- 默认行为：等图片解码，播一次入场（帧在更长页面中时按滚动进入触发），随后故事常驻。

## 8. 静帧校验（动效开工前必过）

在 2 倍下渲染 `?still` 与参考比对：

- **PSNR**：先做轻度模糊（`gblur sigma≈1.2`）再算，避免亚像素抗锯齿主导。整帧 > 35 dB，单容器 > 30 dB。文本密集容器因 3 倍层被重采样到 2 倍常在 30 dB 附近；偏低就改 `sigma≈2.5` 复测，此时只比结构。
- **看差异图**：放大后的模糊差值图能暴露结构错误（辉光偏高、堆叠错、缺描边、阴影位移）。
- **截图源额外校验表面**：抬起层自带表面色，会盖住重建表面的错误并虚高分数。遮掉抬起与裁切区域后再评分，须过同样阈值。
- **不追亚像素**：2 倍下测不出半像素以内误差，“修正”反而过头。修结构，不修抗锯齿。

## 9. 载入编排 (Loading Choreography)

**从空态起**：每次页面加载与每次导出的第一帧都是空态。App 框 = 背景 + 静态贴合表面；独立卡片 = 只有背景。**绝不从成品帧开场。**

| 类型 | 用于 | 起始状态 |
| :--- | :--- | :--- |
| `card` | 独立卡片整体（含阴影） | `translateY(24px)`、`scale(0.985)`、`blur(6px)`、opacity 0 |
| `up` | 文本、标题、数值、行 | `translateY(10px)`、`blur(4px)`、opacity 0 |
| `down` | 顶部工具条、顶栏 | `translateY(-8px)`、`blur(4px)` |
| `left` | 侧栏项、列表行、标签 | `translateX(-10px)`、`blur(4px)` |
| `pop` | 图标、徽标、头像、按钮、圆点 | 自元素中心 `scale(0.82~0.88)`、`blur(4px)` |
| `photo` | 图片 | 先骨架微光，再 `blur(14px) saturate(0.6)` 转清晰；烘焙进大图的照片见第 4 节 |
| `wipe` | 条、填充、高亮 | 按像素的左到右 `clip-path` 揭示（全舞台单元）：右内缩从 `stageW − x`（零宽，无残条）到 `stageW − (x + w)`（完全显示）；上下内缩固定为 `y` 与 `stageH − (y + h)` |
| `line` / `grow` | 分隔线、刻度、时间轴 | 从起始边 `scaleX(0)` / `scaleY(0)` |
| `donut` | 圆环、仪表 | 锥形遮罩自 12 点顺时针扫过 |
| `tray` / `rise` | 抽屉、托盘、文件夹 | 从容器下缘内侧升起 40px，被容器裁剪 |
| `fade` | 被其他层压住的层 | 只改透明度 |

- **顺序**：容器按阅读顺序，间隔 80 到 90ms。App 框按静态表面内的区域，独立卡片按卡（每张卡比其内容早约 0.15s）。容器内部：页头 → 标签 → 数值 → 视觉。同组内元素错峰 30 到 80ms。
- **禁止 `scale(0)`**：只有线与条可以从零生长，因为那是“画出来”。
- **被压住的层最后进、最先出**：终帧里被别的层盖住的东西（托盘下的日历周）在覆盖层落定后出现，溶解时更快退出，避免透影。
- **骨架贴合真实形状**，并内缩 1px，避免载入后出现光晕。
- 整帧入场总时长约 2 到 2.5s。

## 10. 条形按进度填充

- 数据条、仪表、高亮 **按进度条方式填充**：左到右 `clip-path` 擦除，`--io` 曲线，0.7 到 1.1s。
- **绝不新增加载线**：不许在卡片或表面顶边加进度线，也不许出现设计里没有的条或线。只有设计里存在的形状才动。

## 11. 故事循环（主角）

入场只是开场。主角是每个视觉 **演出它自己的功能**：线索列表收到新线索、图表被读取、日历找到空档、提示词被打出。用户说“把视觉动起来”，指的就是这个。只载入再静静跳几下脉冲，不算完成。

**先写故事**：构建前为每个视觉写一句话，例如“一条新线索落到顶部，旧的各退一格”。可从下表选取或按同精神自创。

| 视觉 | 故事 |
| :--- | :--- |
| 条目堆叠（线索、通知、文件） | 新条目带模糊落到顶部，其余退一格，最末一条离开 |
| 折线或面积图 | 游标滑过，圆点贴着曲线走，提示值跳动；或线条重绘，标记弹出，数字同步累加 |
| 柱图、频谱、单元格阵列 | 柱体像实时数据一样起伏后回落到设计高度，圆点与提示贴着当前柱 |
| 圆环、仪表 | 分段逐个向外缓出再回位；或环再顺时针扫一遍 |
| 表格、列表 | 光标逐行检视，行高亮，预览随之载入；或一层柔和高亮逐行下移 |
| 日历、排程 | 高亮搜索空档，事件滑入，再退回 |
| 流程、连接线、管道 | 脉冲沿连接线按流向行进，节点或头像被点亮，虚线行进 |
| AI、提示词、表单 | 提示词删除后重打，条件逐个评估，结果带模糊浮现 |
| 计数器、KPI | 数字与驱动它的图表同步累加 |
| 个人资料、长内容 | 内容在裁剪内缓慢滚动后回位 |
| Logo 行 | 连续跑马灯，每循环恰好平移一整套，无缝重复 |
| 媒体播放器 | 播放头与进度推进，播放按钮脉冲 |

**故事规则**

- **起止都在精确设计上**：每个故事离开 Figma 帧、表演、再回到它。静息时帧必须等于 `?still`。
- **只用设计自己的元素**：卡片、行、条、点、芯片、提示皆来自设计。故事需要的辅助物（光标、重复堆叠项、额外脉冲）要与设计同风格，并在 `?still` 中隐藏。
- **只在该改的时候改文本**：计数器、打字、提示值。其余文本一动不动。
  - **打字**是逐字显示导出文本层，绝不做平滑擦除。用文本 PNG 的空 alpha 列找字形边界；粘连对（`tt`、`/w`、`fi`）没有空列，此时用步数与字符数对齐，把过宽的段在其最淡的列处切开直到数量吻合。每 45 到 70ms 显一个字形，边缘显示光标，空闲时每秒闪一次。删除按同步骤反向，略快。
  - **计数器**需要设计字体的活文本，尺寸与字重精确，静息时落在设计的精确文本上。
- **明显而不忙乱**：有故事的卡片每 1 到 2 秒要有一个清晰动作。故事由节拍构成（脉冲发出、节点点亮、箭头击发），节拍提供节奏。若两秒内看不出此帧是动的，说明故事太怯（“再多点动作”）。冷静类屏幕（文档看板）可按用户偏好加载后静止，问一次即可。
- **纯文本卡片在展演里不配故事**：随卡片升起后静止。不是每张卡都要动，但每个视觉都要动。
- **在最小导出尺寸下可读**：故事在 800×500 GIF 里仍要看得见。移动元素在该尺寸小于约 4px（脉冲点、细线）时，在设计风格内放大、加光晕，或换更大的故事。
- **卡片错峰**：卡片不得齐步走。在阅读顺序上让注意力绕帧游走。
- **每卡一个故事，3 到 8 秒**。短故事可在同一循环内重复（8.6s 故事段里跑两次很常见），第二次可变一个节拍。每次运行结束都要回到静息再溶解。
- 故事由 JS 时钟上的缓动关键帧轨道构成，录制才确定：

```js
// [[time, value], ...] 逐段缓动；value 可为数值或数组
function track(keys, t, ease = easeInOut) {
  if (t <= keys[0][0]) return keys[0][1];
  for (let i = 1; i < keys.length; i++) {
    const [t1, v1] = keys[i], [t0, v0] = keys[i - 1];
    if (t <= t1) {
      const k = ease(Math.min(1, (t - t0) / (t1 - t0 || 1)));
      return Array.isArray(v0) ? v0.map((v, j) => v + (v1[j] - v) * k) : v0 + (v1 - v0) * k;
    }
  }
  return keys[keys.length - 1][1];
}
// 沿曲线擦过再回到设计位
slot.style.transform = `translate(${track([[0, [0, 0]], [1.2, [46, -18]], [2.6, [46, -18]], [3.8, [0, 0]]], t).join('px,')}px)`;
```

**点缀**叠加在故事之上，不能替代故事：

| 点缀 | 用于 | 数值 |
| :--- | :--- | :--- |
| 脉冲环 | 状态点、直播指示、播放按钮 | 周期 1.8 到 2.2s，环 scale 1 → 2.6，opacity 0.55 → 0 |
| 心跳 | 爱心、点赞、星光 | 0.35s 内 +20%，每 3s 一次 |
| 轻浮 | 浮动对象（文件夹、设备、卡中卡） | ±2.6px，2.8s 正弦 |
| 扫光 | 照片、条、按钮 | 带宽为元素宽 38%，峰值 34% 白，每 3.4s 扫一次 1.5s。浅灰形状上会消失，改用“重填”故事 |
| 骨架微光 | 设计内的占位线 | 2.4s 微光 |

- 故事与点缀在入场落定后开始（约 2.4s）。故事从精确设计起步，无需淡入；点缀与辅助物 0.6s 淡入。

## 12. 循环周期（展演）

站点不循环：入场在滚动时播一次，故事跑到分区离开视口为止。

| 阶段 | 默认时长 |
| :--- | :--- |
| 构建入场 | 0 → 2.4s |
| 故事 | 2.4 → 11.0s |
| 溶解 | 11.0 → 11.6s（opacity 0.5s） |
| 空拍 | 11.6 → 12.0s |

- **故事段至少容纳每张卡的一个完整故事**。宁可拉长循环，也不要截断故事；让每张卡在溶解开始时都已回到静息。
- **在线页面入场后永久演故事**。只有 `?loop` 与导出会溶解重启。
- **溶解回空态**：App 框只溶解内容，贴合表面留着；独立卡片连卡一起溶解；背景永不溶解。
- **全量复位**：用一个禁用过渡的类重置一帧 CSS，但所有由 JS 驱动的值（遮罩、轨道、辅助物、已打文字、脉冲）也必须回到空态，否则会在空拍里透影。循环末帧必须等于首帧。

## 13. 缓动与时长

入场绝不使用默认 `ease` 或 `linear`。

| Token | 曲线 | 用途 |
| :--- | :--- | :--- |
| `--e` | `cubic-bezier(0.16, 1, 0.3, 1)` | 入场的位移变换（1.05s） |
| `--e2` | `cubic-bezier(0.33, 1, 0.68, 1)` | 透明度与模糊（0.7 到 0.8s） |
| `--io` | `cubic-bezier(0.65, 0, 0.35, 1)` | 擦除、填充、扫光、相机 |
| `linear` | `linear` | 仅匀速运动（微光、播放） |

展演的时间本来就比产品 UI 慢。产品侧“300ms 以内”的规则在这里不适用，慢而顺才是目标。

## 14. 相机

- **默认不缩放、不平移**，除非用户点名。
- 点名时：只有 App 框朝条目缩放，背景永不移动；位移用 `--io`；溶解前回到静息位。

## 15. 性能与无障碍

- 只动 `transform`、`opacity`、`filter`、`clip-path`。绝不动 `top`、`left`、`width`、`height`。
- 动画中的 blur 不超过 14px；静态 `backdrop-filter` 不受限。
- `prefers-reduced-motion: reduce` 渲染静帧。
- 入场用 CSS transition，时间相关效果用 JS 时钟。

## 16. 动效自检（编码前必过）

在录好的帧上跑：

- **溢出检查**：用容器的真实形状（含圆角）而非矩形。从页面自身渲染遮罩（每个容器按精确圆角画纯白，背景纯黑，有阴影则加阴影区域），外扩 2px 跳过抗锯齿，只比黑像素；此处的 `?still` 按录制的设备缩放比渲染，不用第 8 节的 2 倍。
  - **App 框**：贴合表面之外的每个像素，在整个循环的每一帧都必须与空态首帧完全一致（PSNR `inf`）。
  - **独立卡片**：故事段内，卡片（及其阴影）之外的每个像素都必须与 `?still` 完全一致，任何故事、辅助物、内容都不得离开卡片。入场帧排除在外（卡片自身升起会移动像素），但联系表必须显示内容随卡移动，不得抢先或出界。
- **接缝检查**：导出窗口首帧等于一个周期后的那一帧。
- **空拍检查**：空拍每一帧都等于 `__start` 之前那一帧。接缝检查抓不到未复位的 JS 状态（两帧都在循环时间 0），这项能抓。
- **回位检查**：溶解前最后一帧等于入场结束、第一个故事开始前的落定帧（PSNR `inf`），证明每个故事都回到了设计。再与录制倍率下的 `?still` 比，应非常接近（约 38 dB 以上）但可能不完全相同，因为 Chrome 会以略微不同的方式光栅化跑过过渡的元素；此比对若出现结构性差异即为缺陷。
- **联系表**：把关键时刻（空态、入场中、落定、故事若干点、溶解中、结束）平铺成图，检查溢出、透影、跳变，以及故事是否怯到看不出来。

## 17. 确定性录制

绝不用实时录屏。步进假时钟，逐帧截图。循环是否平滑、接缝是否干净由三个细节决定，全在下面这段里。

```js
await page.clock.install({ time: 0 });
await page.goto(url + "?capture", { waitUntil: "load" });
await page.evaluate(() => document.fonts.ready);
await page.clock.pauseAt(10000);
const loopTime = [];
for (let i = 0; i < frames; i++) {
  // 1. 整毫秒步长，均值精确等于 1000/60（17、17、16…）；runFor(1000/60) 会漂移
  const dt = Math.round((i + 1) * 1000 / 60) - Math.round(i * 1000 / 60);
  await page.clock.runFor(dt);
  loopTime.push(await page.evaluate(([i, PRE, dt]) => {
    if (i === PRE) window.__start();          // 2. 启动与定位在同一次 evaluate 内
    if (i >= PRE) window.__tick(dt / 1000);   // 3. 页面时钟在此推进，绝不靠 rAF
    const now = performance.now();
    for (const a of document.getAnimations()) {  // CSS 过渡跟随假时钟
      a.__m ??= window.__mark;                    // 每个过渡记住自己被创建时的标记
      a.pause(); a.currentTime = Math.max(0, now - a.__m);
    }
    return i >= PRE ? window.__lt : 0;
  }, [i, PRE, dt]));
  await page.screenshot({ path: `${out}/${String(i).padStart(5, "0")}.png` });
}
```

页面侧的 `?capture` 约定：

- `__start()` 加 `in` 类。舞台状态类（`in`、`out`、复位）每次变化都写 `window.__mark = performance.now()`，这样每个过渡都从它被创建的瞬间定位；过渡延迟（`--d`）计入 `currentTime`。
- `__tick(dt)` 推进循环时间，跑周期各阶段，绘制故事与点缀，写 `window.__lt`。
- 永不结束的循环（微光、跑马灯）由 JS 时钟驱动，不用无限 CSS 关键帧（定位会把它重启）。

`PRE` 是启动前录的若干帧（约 15 帧），让页面稳定。`loopTime` 与帧一起保存。

- 视口即帧尺寸。`deviceScaleFactor = min(1920 / W, 1200 / H)`，让长边顶到 X 的上限。截图会取整像素，可能差一个（1440×990 帧得到 1745×1200）；MP4 裁到偶数尺寸会处理掉，预期为 1744×1200。
- **导出窗口**从帧 `PRE − 1`（循环时间 0，空态）开始，长度恰为 `cycle × 60` 帧。再多录至少 10 帧用于接缝检查。

## 18. 导出格式

| 文件 | 规格 |
| :--- | :--- |
| `<name>-x.mp4` | H.264、`yuv420p`、60fps、CRF 14 到 15、preset slow、`+faststart`、上限 1920×1200、偶数尺寸 |
| `<name>-loop.gif` | 宽 960px、15 到 20fps、约 2 到 3MB，用于网页 |
| `<name>-800x500.gif` | 必交付。帧有宽留白时（多数卡片与 Bento 帧）裁到内容并成精确 1.6:1，较紧的一轴留约 40 CSS px 余量，另一轴扩展到位；内容铺满时等比适配并用页面底色补边。照片背景一律裁切，避免照片旁出现纯色带。20fps，重则 12fps |

```bash
ffmpeg -start_number $A -framerate 60 -i frames/%05d.png -frames:v $N \
  -vf "crop=trunc(iw/2)*2:trunc(ih/2)*2" -c:v libx264 -preset slow -crf 15 \
  -pix_fmt yuv420p -movflags +faststart name-x.mp4

ffmpeg -start_number $A -framerate 60 -i frames/%05d.png -filter_complex \
  "trim=end_frame=$N,fps=20,scale=960:-2:flags=lanczos,split[a][b];\
   [a]palettegen=max_colors=192:stats_mode=diff[p];\
   [b][p]paletteuse=dither=bayer:bayer_scale=4:diff_mode=rectangle" -loop 0 name-loop.gif
```

800×500 GIF 在 `split` 前加 `scale=800:500:force_original_aspect_ratio=decrease,pad=800:500:(ow-iw)/2:(oh-ih)/2:color=<页面底色>`。

- 帧内有照片时保留 bayer 抖动，否则会出色带。
- GIF 过大时先降帧率或色数，不要先降尺寸。
