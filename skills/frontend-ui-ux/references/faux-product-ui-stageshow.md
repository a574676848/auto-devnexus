# 示意产品界面与展演方法论 (Faux Product UI / Stageshow)

> 来源：[benjitaylor/skills · stageshow](https://github.com/benjitaylor/skills)（MIT，commit `299140f`，Copyright 2026 Benji Taylor；app-icons 与品牌素材不在 MIT 范围内），按本技能语义重写。
> 本文件是模式 J 的执行规范；动效编排细则另见 `motion-and-interactions.md`，设计稿保真重建与确定性录制见 `design-to-motion-showcase.md`。

**一句话**：做一个可信的微型产品界面，放进它该在的空间里，只需一个静帧或一段「只有一件事发生」的短动画。观众认出这是那个屏幕，并看见那件事发生。

---

## 1. 一个核心想法与五种失败

**核心想法**：读起来像真产品，简化到观众需要的程度，按意图裁切画面，每个动作都有原因。

| 失败形态 | 症状 | 根治 |
| :--- | :--- | :--- |
| **过载 Too much** | 每行都是真文字，满屏数字，塞得很满 | 细节越多越像生成的。只给故事相关的真词，其余用占位条 |
| **线框 Wireframe** | 两个灰块加一个按钮，做得太小，或被剥掉了可识别性 | 该有的结构、文字、内容密度不能省 |
| **盒子化 Boxed** | 整个窗口缩进卡片，四边留白均匀，像贴了一张截图 | 裁切、出血、让窗口跑出边缘，不是把窗口装进框 |
| **扁平 Flat** | 每个对象权重相同，都在同一张描边卡片里 | 眼睛要有落点：比例、空间、材质、底色制造层级 |
| **寡淡 Bland** | 不管 Brief 说了什么都给一个灰窗口加光标 | Brief 的气质（蓝图、玻璃、灵动岛、吉祥物）才是重点，要按规则把它做到位 |

**代价提醒**：空角、列表下方的空洞、行距拉开硬撑满面板、窗口浮在一块底板上，这些读起来是「没做完」，不是「克制」。

**这不是浏览器自动化**：`a.click()` 画出光标按下的动作，`a.set()` 切换场景，一切是编写出来的演示，不是真去点。

## 2. 工作流七步（质量在写代码前就定了大半）

先写计划：放在哪里、焦点对象、动作、回报、可以删掉什么。

### 第 1 步：媒介与位置
- 静帧还是动画（循环、进入视口播一次、悬停播放）。
- 设计尺寸按最终被看到的尺寸来：页头旁 ≈ 720 × 340；通栏页头 900 到 1100 宽；卡片 400 × 300 按 1:1 展示；演示主体别低于约 320 宽（bento 单格或附属小卡可以更小）。
- 任何可能落进手机单列的演示，都要另出一版手机列宽的 `compact` 设计（约 358 宽），是重新设计而不是压缩。
- 一组 bento 图块按一个整体规划。

### 第 2 步：外观
- 拿到产品代码或站点时，把它的 token 映射到自己的 token；开发者要求用他们自己的组件时，就在舞台里用他们的组件，而不是自己的小部件。
- 否则先定主题（浅色、暗色、蓝图、玻璃）、配色（强调色、单色）与保真度：`minimal` 全是占位条；`standard` 有意义处用真词，其余占位条；`realistic` 处处真实内容。
- 默认浅色 + 强调色 + `standard`；在页头尺度、有具名真实产品、或静帧主题本身就是列表/文档页面时，升到 `realistic`。
- 保留产品自身的图标、自身的 chrome、让它可识别的那些内容。
- Brief 带风格（kawaii、纸张质感、海报配色）就完整给它，但依然按本文件的规则构建。

### 第 3 步：故事
- 选择故事形状：使用起来的感受、一条流程、还是系统在做什么。
- 三到五个节拍加一个回报，总长 10 到 16 秒。
- 没有解释不了的光标移动。数据在视野内不得无原因回退。
- 故事更丰富与画面更安静冲突时，选画面。

### 第 4 步：从范例起步
- 先找出最接近的范例并把它放出来看，把它的目录整体复制成起点，**不要看一眼就重写**。
- 保留它的结构：舞台尺寸、裁切与出血、行高与字号、间距、脚本节拍、组件用法。
- 然后替换为 Brief 的产品：token、产品自己的图标、chrome 和措辞。只改名字不算完成，它必须读起来是 Brief 的产品。
- 没有范例能讲你的故事时，分两步选：先按版式表选版式（照抄那个范例的结构），再从故事最接近的范例借动作编排，两者都没有的部分按同一风格自建。
- 然后做裁切：只裁到故事发生的那个面板，按最终可见的裁切来判断。短版规则：一条排水沟，要么完整留出要么远远越过；只有占位内容可以出血；会打开的东西留在画面内；窗口保持自己的形状；页面就是底色，白底或暗底页头下不加底板；不允许四边均匀留白的完整窗口；没有死掉的角。


### 第 5 步：屏幕本身
- **数真字符串**，通常 3 到 7 个：这是词预算，不是元素预算。
- 用统一的 token 与小部件（占位条 `Bar`、文本 `Text`、行 `Row`）搭建；列表一律由行构成，手搓行是列表出错的根源。
- 每个控件在动之前先把文字装好，边框盒要容纳内容加内边距加边框。
- 光标要触碰的元素标 `data-target` / `data-cursor`，用测量函数量矩形，**绝不硬编码坐标**。

### 第 6 步：编排动作
- 出现的元素保持挂载并用状态切换，这样离场也有动画；不要让元素重新挂载。
- **动关系，不只是动对象**：新行插入时带动下方行，表面改变尺寸时不拉伸里面的文字。
- 节拍之间要重叠，同组错峰，回报要停留，循环结束时回到起点，或以可见的原因重置。

### 第 7 步：彩排与验收
- **先定海报帧**：多数人只看那一帧（缩略图、减弱动效、截图）。海报帧必须自己就能讲故事，不能是变化中途的帧，结果要留在屏幕上而不是被收拾干净。
- 录整段循环而不只是静帧，按展示宽度与 390 宽各出一张联系表（contact sheet），逐格看每一次按下、菜单展开、形变与循环接缝。
- 逐帧读，**先修最大的可见缺陷**：裁切 → 层级 → 动作 → 打磨，改完重录。
- 把成品与最接近的优秀范例并排，回答两个问题：眼睛第一落在哪，是不是回报？是否有一个窗口、图块或设备明显主导？任一为否就是最大缺陷。
- 时间或调用次数紧张时，修彩排列出的线优先于再多出静帧、评审和说明。通过是必要条件，不是充分条件。

## 3. 静帧工艺规则（写代码前就该知道）

### 3.1 克制
- **词预算是词，不是元素**：日历需要排满的一周，搜索需要一批结果，筛选需要足够的行。
- **占位条是产品的填充物，主题才用真词**。眼睛落点上出现灰条会读成没做完。
- 静帧里主题必须是真实的（词与数值）；旁边的侧栏或列表用条是允许的填充。
- 小尺寸表面上，一行只有一条信息：弹层、卡片、图块里放头像、名字、数值。真名字下面再加灰条会被读成噪音。
- 有名字的头像用自己的颜色，灰盘只当填充。标签与数值必须匹配：都是词或都是条；真控件旁边挂一个空白药丸是死的，不如不放。
- **保留行业的签名内容**：专辑封面、缩略图、头像。换成功能信号就变成通用列表。
- **把最重的视觉质量放在故事主体上**，绝不在灰条下面加一条 2px 黑下划线来强调。
- 空间跟着故事走：回报要拿到空间，不要把结果挤进裁切边。
- 一句话只说一次：功能的信号不要同时出现在标题、附属卡和每一行。
- **虚构品牌不要做刊头**：每张裁切里都放字母标、logo、侧栏和导航是错的。只有识别确实需要时才放真实标志；产品名只在 Brief 依赖它、且真实产品会在那出现时才出现（通知的应用名、应用自己的标题栏）。
- 先简化再打磨：能解释产品的最少表面与字符串，边框与徽标只在挣得之后加。简化要保留性格，先砍重复的画框，而不是把内容砍成空白卡片。
- **先判断剪影，再看细节**。缩略图尺寸下，主体、支撑与留白应构成一张画。
- 组合对象，不要堆卡片清单。层级来自比例、空间、材质和底色，不是更多盒子。
- 圆点、光环、徽标、焦点环必须完整落在内容边界内；图像要在最小尺寸、以及它跨过的每个表面上检查，浅色缩略图可能看起来像透明的。
- 什么都不许超规格：页头元素与真实屏幕成比例。

### 3.2 文字
- **先让文字装得下，再固定盒子**；小字行高不低于 1.3，四周留内边距。
- 用真实字号再整体缩放：界面文字 11 到 15 px，绝不出现 7 px 的字。
- **一个字族**，代码、标识符、对齐数字才用等宽。技术产品的标签不用等宽。
- 只保留识别产品与跟随节拍所需的文字；多余的日志和时间戳是噪音。
- 默认句首大写，除非真实产品本身用全大写；层级靠间距与一级字重差。
- **不用真标题**：假应用的标题是 `div`，绝不是 `h1` 到 `h6`，因为演示活在别人的页面大纲里。

### 3.3 间距与对齐
- 按钮距上方的输入框、分隔线或卡片边缘保留 8 到 12 px：贴上会读成粘连，太远又会从所属控件上飘走。
- 浮动卡片（评论弹层、提示条）四边等距，按头像与按钮的边缘量，而不是按它们的文字量。
- 文字距窗口、卡片、面板、悬停行的边缘保留 12 px 内缩，低于 8 px 算过紧；条可以出血，文字不行。
- 行内边距 12 px（密集列表 8 px）；一行文字却有三倍高度的行是胖行。
- 标题与副标要像一条：行间距 4 到 6 px 墨迹，行高 1.3 加 2 px 间隙，空气来自行的内边距。
- 占位条与它替代的文字在同一行盒里，骨架行的节奏才和真实行一致；条保留的是文字间的空白，不是行距。
- 文字绝不贴邻接盒子：固定 8 到 12 px 间距，绝不靠 `space-between` 的余量。
- 标志（标签）按字母居中，不按行盒居中：`text-box: trim-both cap alphabetic`。
- 嵌套形状等距内缩，外圆角 = 内圆角 + 内边距；底部也要延续同样的内缩。
- 列要对齐：所有行共用一套网格模板与固定轨道，可选内容保留空轨道，条在轨道内变宽。
- 不留近切线：1 到 3 px 的边缘距离读成事故，要么精确对齐，要么拉开到至少一个间距（不小于 8 px）。
- 金额居中要居中数字：货币符号挂在数字左侧之外，滚动时只滚数字。
- 悬停与选中填充要内缩并圆角；打开弹层的触发元素要保持按下态。

### 3.4 图标与标志
- 图像要挣得位置：真实图像或好图标，绝不自创插画；灰色插画只用于空状态。
- **图标必须来自图标集，不能手画**。手画字形是「生成的界面」的第一个破绽，笔画粗细永远配不上邻居。优先产品自己的图标包，否则有意识地选一套（Phosphor、Iconoir、Radix、Tabler、Heroicons；Lucide 不是默认反射）。
- 一套字族、一种描边粗细、一个尺寸（14 到 16 px）；14 px 及以下、着色图块里用实心样式。
- 图标是不透明单色，靠 `opacity` 做淡出，不做双色。
- Emoji 是内容，不是图标。别的产品的标志要用真实资产、原始比例与颜色，绝不画相似图形。
- AI 功能不要闪光、魔杖、星星，不要紫色。展示 AI 做了什么就行。
- 不发明 logo：彩色方块里放一个字母不是产品标志。

### 3.5 颜色与外观
- 窗口、侧栏、卡片使用同一套中性色族；有颜色的底或另一种材质要出于明确意图。
- 起手五个墨色加一个强调色；状态色只表示状态。不要冗余的同色调描边，先只靠填充。
- 安静不等于看不清：在真实底色上检查文字、操作与表面。
- 渐变或光晕要服务故事，否则删掉。
- 用来讲故事的那张卡片，不要给它描边加光环来指认，那是没人给的焦点态；该像真实产品那样抬起来：自己的表面、抬升的阴影、强调色的标签。
- 单个元素绝不靠半透明叠加来造层级；重叠头像要用不透明色阶。
- 暗色主题的深度来自更亮的表面，不是阴影。
- **浅色版通过不代表暗色版成立**：请求里点到的每个外观都要真的看一遍。

### 3.6 设备与 chrome
- **框架有帮助才用**：浏览器 chrome 只在「浏览器本身是画面的一部分」时才出现；桌面应用用它真实的 chrome。
- 列要跑满窗口高度，中途停下的列会留下接缝；窗口 chrome 高度固定 38 px。
- **绝不凭记忆画平台 chrome**，先打开真实应用或截图。
- 手机来自套件，状态栏与 Home 指示条由手机框提供，绝不手画；灵动岛下方不许压任何东西。
- 手机从第一帧就是亮的，绝不被压暗、变黑或淡入。
- 手机可以跨越窗口，但绝不遮住它要解释的那个数值。
- 多窗口时选定当前步为活跃窗口，其余用更安静的对比与阴影后退。

## 4. 每轮都会复发的缺陷清单（交付前逐条核对）

| 缺陷 | 规则 |
| :--- | :--- |
| 内容用替换而不是移动 | 文字与数值变化要沿用同一元素做位移或滚动，不要瞬间换内容 |
| 灰条出现在眼睛落点上 | 占位内容只放边缘 |
| 窗口后面垫底板，或窗口四边留白漂浮 | 窗口或手机至少占舞台三分之二，并跑出至少一条边 |
| 空带、被切掉的控件、多余阴影 | 结果区不能有空洞，控件不能被裁掉一半 |
| 通用 AI 味与自造 logo | 不要闪光、紫色、彩色方块字母 |
| 行太挤、内缩不均 | 行内边距与四边内缩按 3.3 节 |
| 长时间空等、无原因重置 | 循环结尾要么回到起点，要么给一个可见原因 |
| 选中态不在 I 型光标下 | 拖选时选区必须贴着光标 |
| 手画状态栏或 Home 指示条 | 一律由手机框组件提供 |
| 居中金额连符号一起居中 | 只居中数字 |

## 5. 一页多个演示时的统一性

- **一套图形语言**：一个底色、一个间距、一种窗口阴影、一套圆角。换了阴影要么有含义，要么是错误。
- 更少但更强的演示：能用演示说明的地方，不要再放带标签的小容器或文字块。
- 并列对比的那一对要用与上一组不同的演示。
- 反例用本页自己的标注语言标出，绝不画叉或乱涂。
- 把 CSS 作用域收在演示根类下（`@keyframes` 除外）；仅加前缀不够。宿主页面用 `:not(:where(.某舞台 *))` 把自己的排版样式排除在演示之外。
- `compact` 是手机列的第二套设计，不是压缩版。
- 每个宽度都重新加载一次、也在两个宽度之间改一次尺寸，检查目标、裁切、浮层与海报帧。

## 6. 在本技能里怎么落地

**默认不用套件，直接写 React + CSS 复现这套规则**。上游的 React 套件（`kit/`，含舞台、窗口、手机、气泡、图表、光标等组件）与 30 多个黄金范例是取之不尽的参考，但体积大、依赖 `react-dom` 与 `lucide-react`，不适合塞进本技能。需要原样调用时按上游安装：

```bash
npx skills add benjitaylor/skills --skill stageshow
# 或在本地克隆后 npm install && npm run dev 打开 examples 预览
git clone https://github.com/benjitaylor/skills
```

**自行实现时的最小映射**

| 上游概念 | 本项目等价做法 |
| :--- | :--- |
| `Stage`（设计尺寸 + 缩放适配 + 场景状态 + 播放） | 固定设计尺寸容器 + `transform: scale()` 适配 + 场景状态机 |
| `Window` / `Phone` 帧 | 真实比例的窗口与手机外框组件，含真实状态栏与 Home 条 |
| `Act` 脚本（`set`/`wait`/`move`/`click`/`type`） | 时间轴数组 + 假时钟驱动的状态推进，不依赖真实定时器 |
| `Bar` / `Text` / `Row` | 占位条、文本、行三个基础组件，全部走 token |
| `Collapse` / `Roll` / `Swap` / `Count` / `Fly` / `Follow` | 见 `motion-and-interactions.md` 的等价动效实现 |
| `film.mjs` 录制 | 见 `design-to-motion-showcase.md` 的假时钟逐帧截图 + ffmpeg 三件套 |

**校准练习（上游作者的测试法）**：复刻自己每天在用的应用里的小片段（在 Figma 里打开取色器改按钮颜色、在 Gmail 里归档一封邮件、在 Finder 里把文件拖进文件夹、在 Spotify 里切歌），同一段 Prompt 对比加不加本规范的效果差。这是检验规范有没有真正落地的唯一办法。

**边界**：示意界面用于营销页、功能卡、文档页头、产品演示。它是插画，不是真实应用，绝不能让它承担真实交互职责；反过来，真实产品页面里的截图区也不要塞这种假界面来冒充产品截图。
